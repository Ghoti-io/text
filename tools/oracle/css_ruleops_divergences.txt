# tools/oracle/css_ruleops_diff.py: the divergences of the rule operations between this library and Chromium 156.0.8078.47 / Firefox 158.0.1 that are not defects of the library. Tab separated: feature, class, count in the default population (seed 1, 200 documents), reason.
I:IndexSizeError/IndexSizeError/SyntaxError	served-text	26	CSSOM, CSSStyleSheet.insertRule: "Let parsed rule be the return value of invoking parse a rule with rule. If parsed rule is a syntax error, throw a SyntaxError DOMException" comes before "insert a CSS rule", whose first step throws IndexSizeError for an index greater than the length; Chromium 156 and Firefox 158 both look at the index first, so a text that is not one rule, with an index past the end, is IndexSizeError there and SyntaxError here (an @import into a constructed sheet is the same).
I:InvalidStateError/HierarchyRequestError/HierarchyRequestError	browsers-differ	1	CSS Namespaces 3: an @namespace rule follows the @charset and @import rules and precedes all other rules, so one inserted after a style rule violates the constraints and CSSOM throws HierarchyRequestError before it looks at what the list holds; Firefox 158 answers so and Chromium 156 answers InvalidStateError, and this library keeps the served order.
I:SyntaxError/HierarchyRequestError/SyntaxError	browsers-differ	10	A text that is not exactly one rule (an @import followed by a rule), or an @charset, which a style sheet has no rule for, is dropped by "parse a CSS rule" and is a SyntaxError; Chromium 156 answers so, and Firefox 158 reads the first rule of the text or the @charset as a rule and answers HierarchyRequestError for the place; this library keeps the served text.
I:SyntaxError/InvalidStateError/SyntaxError	browsers-differ	1	An @namespace with neither a prefix nor a URL is not a rule, so "parse a CSS rule" is a syntax error and CSSOM throws SyntaxError; Chromium 156 answers so and Firefox 158 answers InvalidStateError, as if it had read an @namespace rule; this library keeps the served text.
rules:@keyframes	browsers-differ	10	CSSOM writes a CSSKeyframesRule as "@keyframes", the name, then its rules separated by a newline and indented by two spaces, and the draft says that this "needs work" (csswg-drafts 5494): Chromium 156 writes the name and then " { " and a newline, Firefox 158 writes no indentation, and this library writes one keyframe to a line indented two spaces with an empty rule as "{ }", as the typed model of the at-rule does.
I:HierarchyRequestError/ok/ok	browsers-differ	0	CSS Cascade 5 lets an @layer block be nested in a style rule and CSSOM inserts a rule the place allows; Firefox 158 accepts an @layer block inserted into a style rule, as this library does, and Chromium 156 answers HierarchyRequestError.
I:InvalidStateError/HierarchyRequestError/InvalidStateError	browsers-differ	0	An @namespace inserted after an @layer statement into a list that holds a style rule: the draft says nothing about whether a statement is a rule that an @namespace must precede, Chromium 156 and this library answer InvalidStateError (the list holds more than imports and namespaces) and Firefox 158 answers HierarchyRequestError.
I:SyntaxError/ok/HierarchyRequestError	browsers-differ	0	A style rule inserted into an @page: the rules of an @page are its margin rules, so the place does not allow it (HierarchyRequestError here); Chromium 156 reads the selector as a page selector and answers SyntaxError, and Firefox 158 accepts a style rule into the @page.
I:SyntaxError/ok/SyntaxError	browsers-differ	0	An @layer statement inserted into an @page is not valid there (CSS Cascade 5 puts a statement at the top of a sheet or in a grouping rule); Chromium 156 and this library answer SyntaxError and Firefox 158 accepts the statement into the @page rule.
I:SyntaxError/ok/ok	browsers-differ	0	A text of declarations then a rule (color:red; c{}) inserted into a style rule: parse a rule fails, the declarations are read as a list of declarations and a non-empty result is a nested-declarations rule, which Firefox 158 and this library do; Chromium 156 answers SyntaxError.
I:ok/SyntaxError/SyntaxError	browsers-differ	0	A rule followed by a declaration (c{} d:e) is not one rule, so parse a rule is a syntax error and, with no valid declaration, so is the fallback; Firefox 158 and this library answer SyntaxError and Chromium 156 reads the rule and ignores the rest.
I:ok/SyntaxError/ok	reference-wrong	0	Counter Styles 3 defines "system: fixed <integer>?" with the integer optional (the first symbol has the value 1), so @counter-style c{system:fixed} is a valid rule; Firefox 158 rejects it with SyntaxError and Chromium 156 and this library accept it (Chromium writes the default as "fixed 1", this library as "fixed").
rules:@counter-style	browsers-differ	0	Chromium 156 writes the default first-symbol value of "system: fixed" as "fixed 1" and this library as it was written, "fixed"; Firefox 158 rejects the rule.
I:HierarchyRequestError/HierarchyRequestError/ok	served-text	0	CSS Cascade 5: "Any @import rules must precede all other valid at-rules and style rules in a style sheet (ignoring @charset and @layer statements)", and this library parses and inserts by that sentence, so an @import after an @layer statement is valid; Chromium 156 and Firefox 158 both read a sheet so, and both refuse the same @import when it is inserted after a layer statement with HierarchyRequestError.
