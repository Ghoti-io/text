# The differences between this library and the two references of the Encoding differential (tools/oracle/encoding_diff.py), each explained by the
# standard's own data and counted: "the standard decides", and the decision is read by the script from third_party/encoding/indexes.json and
# encodings.json, not from the library (whose tables a different program generates from the same files).
#
# reference <TAB> population <TAB> class <TAB> count <TAB> why
#
# A class is the encoding (or label target) the reference differs about; the count is of what the population counts (label spellings, or
# (byte, mode) pairs, or code points). The run fails on a divergence with no line here, on a line whose divergence is gone, and on a line whose count
# has changed: a difference that moves is a difference to read, not to re-record. Hunts with other sizes (ENCODING_ORACLE_COUNT and the rest) check that
# every divergence has a line and not the counts.
#
# Where the references AGREE with the library and the standard - which is most of the work - there is no line: UTF-8 and UTF-16LE/BE decoded by Node over every sequence
# of one, two and three bytes (replacement mode: all 16,843,008 of each; fatal mode: all of one and two bytes, one in 13 of three; and once, outside the
# gate, all of three), by Python over all of one and two bytes and one in seven of three; the 228 labels in 14 spellings; every other byte of every other
# single-byte encoding; 60,000 random streamed strings; 15,000 UTF-8 encodes; the sniffing of a byte order mark against Python.
#
node	labels	replacement	48	Node refuses the six labels of the replacement encoding (hz-gb-2312, iso-2022-cn, iso-2022-cn-ext, iso-2022-kr, csiso2022kr, replacement) in all 8 of their spellings that the standard trims to a label: that is the Encoding API's TextDecoder constructor ("If encoding is failure or replacement, then throw a RangeError."), not the label algorithm, which this library implements ("get an encoding": "If label is an ASCII case-insensitive match for any of the labels listed in the table below, then return the corresponding encoding"). The labels resolve here because HTML needs them to.
node	labels	iso-8859-16	8	Node has no converter for ISO-8859-16 (ICU lacks it) and throws for its one label in its 8 spellings; the label table has it ("iso-8859-16"), so this library resolves it. Node does not implement an encoding the standard lists ("User agents must not support any other encodings or labels" is about the converse).
node	labels	x-user-defined	8	Node has no x-user-defined (ICU lacks it) and throws for its one label in its 8 spellings; the standard's TextDecoder constructor excludes only failure and replacement, and section 14.5 defines the decoder and encoder.
node	single-byte	ISO-8859-16	512	Node cannot construct an ISO-8859-16 decoder at all (see the label line above): 256 bytes in two modes. The standard's section 9 lists ISO-8859-16 and its index (indexes.json "iso-8859-16").
node	single-byte	IBM866	6	ICU's IBM866 swaps three C0/DEL controls (0x1A, 0x1C, 0x7F) as IBM code page 866 does; the standard's single-byte decoder says "If byte is an ASCII byte, then return a code point whose value is byte." Bytes 0x1A, 0x1C and 0x7F in two modes. (The suite's textdecoder-mistakes.any.js has the test Node fails, which this library passes.)
node	single-byte	KOI8-U	4	ICU's KOI8-U has box-drawing characters U+255D and U+256C at 0xAE and 0xBE; the standard's index koi8-u (indexes.json) has U+045E and U+040E there (the RFC 2319 form). Two bytes in two modes.
node	single-byte	windows-1252	54	Node decodes the label as ISO-8859-1, so 0x80 to 0x9F come out as the C1 controls: 27 bytes (32, less the 5 the index also maps to the C1 control of the same value) in two modes. The standard: "any software following this standard will, for example, decode 0x80 as U+20AC (€) when asked for the \"Latin1\" or \"ASCII\" decoding of that byte." (Node issue 40091; the suite's textdecoder-mistakes.any.js has the tests.)

node	ignore-bom	windows-1252	1	With ignoreBOM: true Node drops a leading 0xFF of a windows-1252 stream (0xFF 0x41 decodes as "A"). The standard reads the flag only for UTF-8 and UTF-16: "If decoder's encoding is UTF-8 or UTF-16BE/LE, and decoder's ignore BOM and BOM seen are false" (the serialize I/O queue algorithm), so for windows-1252 it changes nothing and the answer is U+00FF then "A".
