# The differences between this library and the two references of the Encoding differential (tools/oracle/encoding_diff.py), each explained by the
# standard's own data and counted: "the standard decides", and the decision is read by the script from third_party/encoding/indexes.json and
# encodings.json, not from the library (whose tables a different program generates from the same files).
#
# reference <TAB> population <TAB> class <TAB> count <TAB> why
#
# A class is the encoding (or label target) the reference differs about; the count is of what the population counts (label spellings, or
# (byte, mode) pairs, or code points). The run fails on a divergence with no line here, on a line whose divergence is gone, and on a line whose count
# has changed: a difference that moves is a difference to read, not to re-record. Hunts with other sizes (ENCODING_ORACLE_COUNT and the rest) check that
# every divergence has a line and not the counts.
#
# Where the references AGREE with the library and the standard - which is most of the work - there is no line: UTF-8 and UTF-16LE/BE decoded by Node over every sequence
# of one, two and three bytes (replacement mode: all 16,843,008 of each; fatal mode: all of one and two bytes, one in 13 of three; and once, outside the
# gate, all of three), by Python over all of one and two bytes and one in seven of three; the 228 labels in 14 spellings; every other byte of every other
# single-byte encoding; 60,000 random streamed strings; 15,000 UTF-8 encodes; the sniffing of a byte order mark against Python.
#
#
# ---- the multi-byte encodings (tools/oracle/encoding_mb.py) -------------------------------------------------------------------------------------------------
#
# Populations: mb-decode-N, every sequence of N bytes (1 to 3) in replacement mode; mb-decode-N-fatal, the same in fatal mode (one line for each of the three ways the
# results can differ); mb-decode-4-valid-form (every four-byte form of gb18030's long characters), mb-decode-4-boundary (every sequence of four bytes over the 36 bytes
# that some decoder's rule mentions), mb-decode-4-random-K (four bytes from random sets of 24) and mb-decode-iso-2022-jp-escapes (six bytes over the 11 bytes of ISO-2022-JP's
# escape sequences); mb-encode (every code point through each encoder); mb-encode-text (random text through the encoders).
#
# The class of a decode is the shape of the difference: std=, ref= the classes of the standard's output and of the reference's (A ASCII, C a C1 control, F U+FFFD, P private use,
# U any other character), cut= how the standard's handler cut the bytes (ok a character, err an error, rst an error that restores the byte it looked at), rel= how the two
# characters relate, and the lead and trail bytes it covers. Three kinds of line are **aggregates by construction**, not described by a shape, and they are named so:
# "composed" counts the sequences whose difference is made of differences of shorter pieces (an exact equality of both outputs with the concatenation of the pieces' outputs,
# for the standard and for the reference, each with its own way of cutting) - they add no kind of difference to the populations of fewer bytes; "uncomposed" counts, in the
# stratified populations, what the pieces do not explain (the reference's state); and the three kinds of fatal-mode line (the standard fails and the reference decodes, the
# reverse, both decode differently) count the sequences by whether they are errors. Each of the three ends in `sig=XXXXXXXX`, the sum modulo 2^32 of a checksum of every member (its
# bytes and the outputs of the standard and of the reference), so that the line fixes the exact set, not only its size: a member that moves out of a class, or a new one
# that moves in, changes the line. Their reasons are templates (the same words for every aggregate of a kind), which is why tools/oracle/encoding_mb_witnesses.txt holds, for
# each kind and each reference, a short sequence worked out by hand from the standard that is checked on every run. For every line the library's output is the
# standard's (checked against encoding_model.py and the C++ model of tests/encoding_cjk_model.h, the handlers written again over indexes.json, for **every** sequence of
# every population and not only the ones that differ), so the difference is the reference's.
#
