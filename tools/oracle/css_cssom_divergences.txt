# tools/oracle/css_cssom_diff.py: the divergences of the CSSOM operations between this library and Chromium 156.0.8078.47 / Firefox 158.0.1 that are not defects of the library (class `ours` is, and is bounded by CSS_CSSOM_ORACLE_MAX_OURS). Tab separated: feature (the group of the document, the operation, the three answers), class, count in the default population (seed 1, 500 documents), reason: a served sentence and what each browser answers. The group `page-prop` is the page-property list of Paged Media 3, Appendix A, asked of every property in the two contexts.
decl-cssText-set:V:cssText:text:CF|O	reference-old	1	CSS Sizing 4 defines size as the shorthand of width and height and the pin lists it, so a declaration block that holds both writes the shortest form (size: 1px 2px); neither Chromium 156 nor Firefox 158 ships it (css/css-sizing/size-shorthand-serialization.tentative.html is the tentative page) and both write the two longhands.
decl-cssText-set:V:cssText:text:CO|F	browsers-differ	10	Firefox 158 keeps in an @page only the descriptors it knows (margin, size, page-orientation, marks, bleed) and drops the other page properties that Paged Media 3, Appendix A lists ("This list defines the page properties"), such as color, direction and width; Chromium 156 and this library keep them.
decl-cssText-set:VL:text:CF|O	reference-old	1	The pin lists background-tbd as a longhand of the background shorthand (CSS Backgrounds 4 placeholder, one appended longhand per shorthand), so the length of a block that holds background is ten here and nine in Chromium 156 and Firefox 158, which write the same shorthand.
decl-cssText-set:Y:TypeError/TypeError/ok	served-text	12	CSS Counter Styles 3 gives CSSCounterStyleRule "interface CSSCounterStyleRule : CSSRule" the attributes name, system, symbols, additiveSymbols, negative, prefix, suffix, range, pad, speakAs and fallback and no style, so rule.style is undefined in Chromium 156 and Firefox 158 (a TypeError on a call); this library gives a rule whose block the typed model reads a declaration object, which a binding does not expose for this interface (the ledger row has no style member).
decl-cssText-set:Y:ok/NotSupportedError/ok	browsers-differ	12	Firefox 158 throws NotSupportedError when a declaration list is assigned to the style of a CSSFontFaceRule and leaves the rule as it was; Chromium 156 and this library accept the assignment and keep the descriptors the list names, which are none of color or margin, so the rule is left empty.
decl-cssText-set:rules:@keyframes:text:C|F|O	browsers-differ	8	CSSOM writes a CSSKeyframesRule as "@keyframes", the name, then its rules separated by a newline and indented by two spaces, and the draft says that this "needs work" (csswg-drafts 5494): Chromium 156 writes the name and then " { " and a newline, Firefox 158 writes no indentation, and this library writes one keyframe to a line indented two spaces with an empty rule as "{ }", as the typed model of the at-rule does.
decl-sequence:Q:text:C|FO	reference-wrong	1	CSSOM, removeProperty(): "Let value be the return value of invoking getPropertyValue() with property as argument" before anything is removed, and getPropertyValue of the shorthand margin is the serialization of its four longhands; Firefox 158 and this library return it and Chromium 156 returns the empty string for a shorthand.
feature-map:V:cssText:text:C|F|O	browsers-differ	1	CSS Fonts 4, 13.2 shows only the canonical single block of a @font-feature-values rule and CSSOM gives no layout for it: Chromium 156 writes the whole rule on one line, Firefox 158 writes each block and declaration on a line with no indentation, and this library writes one block to a line indented two spaces.
feature-map:W:TypeError/TypeError/ok	served-text	1	CSS Fonts 4, 12.2: "readonly attribute CSSFontFeatureValuesMap historicalForms" is an attribute of CSSFontFeatureValuesRule in the IDL; neither Chromium 156 nor Firefox 158 has it (tools/oracle/css_cssom_idl_probe.json), and this library does.
feature-map:W:ok/TypeError/InvalidAccessError	reference-wrong	4	CSS Fonts 4, 12.2: "If the associated feature value block only allows a limited number of values, the set() method throws an InvalidAccessError exception when the input sequence to set() contains more than the limited number of values", and the method "throws an exception if an invalid number of values is passed in" (an empty sequence); Chromium 156 stores two values in @swash and an empty one, Firefox 158 has no value maps, and this library throws.
feature-map:W:ok/TypeError/ok	browsers-differ	5	Firefox 158 has no value maps on CSSFontFeatureValuesRule (tools/oracle/css_cssom_idl_probe.json), so set() is a TypeError there; Chromium 156 and this library implement CSSFontFeatureValuesMap as CSS Fonts 4, 12.2 defines it and write the same rule.
media-item:MA:ok/NotFoundError/ok	reference-wrong	1	CSSOM, appendMedium(): "Let m be the result of parsing the given value. If m is null, then return.", and the empty text parses to no media query, so it is null and nothing happens; Firefox 158 throws NotFoundError for appendMedium(""), Chromium 156 and this library return.
media-item:V:conditionText:text:CO|F	reference-wrong	3	CSSOM, appendMedium(): "If comparing m with any of the media queries in the collection of media queries returns true, then return." and "To parse a media query ... return null if more than one media query is returned"; appending Screen to a list that holds screen, or a text that is two media, changes nothing in Chromium 156 and this library, and Firefox 158 moves the medium to the end (print, screen) or appends the text unparsed (bogus).
media-text:V:conditionText:text:CF|O	ours	1	Chromium 156 and Firefox 158 write the unclosed parenthesis of the query screen and ( as it was written and this library closes it (screen and ()) because it serializes the simple block of the media query with its closing token; no served sentence of CSSOM or Media Queries 4 says how an unfinished general-enclosed is written, so the browsers' agreement decides. Owner: the media query serializer of the condition layer (C4).
nested-run:V:cssText:text:CF|O	served-text	6	CSS Syntax 3, consume a block's contents: "If an invalid rule error was returned: If decls is not empty, append decls to rules, and set decls to a fresh empty list of declarations.", so the declarations on either side of a nested rule that is invalid are two lists and become two rules (a style rule and a nested declarations rule); Chromium 156 and Firefox 158 both write them as one block.
order:I:IndexSizeError/IndexSizeError/SyntaxError	served-text	3	CSSOM, CSSStyleSheet.insertRule: "Let parsed rule be the return value of invoking parse a rule with rule. If parsed rule is a syntax error, throw a SyntaxError DOMException" comes before "insert a CSS rule", whose first step throws IndexSizeError for an index greater than the length; Chromium 156 and Firefox 158 both look at the index first, so a text that is not one rule, with an index past the end, is IndexSizeError there and SyntaxError here (an @import into a constructed sheet is the same).
order:I:InvalidStateError/HierarchyRequestError/HierarchyRequestError	browsers-differ	1	CSS Namespaces 3: an @namespace rule follows the @charset and @import rules and precedes all other rules, so one inserted after a style rule violates the constraints and CSSOM throws HierarchyRequestError before it looks at what the list holds; Firefox 158 answers so and Chromium 156 answers InvalidStateError, and this library keeps the served order.
order:I:SyntaxError/HierarchyRequestError/SyntaxError	browsers-differ	1	A text that is not exactly one rule (an @import followed by a rule), or an @charset, which a style sheet has no rule for, is dropped by "parse a CSS rule" and is a SyntaxError; Chromium 156 answers so, and Firefox 158 reads the first rule of the text or the @charset as a rule and answers HierarchyRequestError for the place; this library keeps the served text.

page-prop:page:unlisted:C1F1O0	served-text	2	Paged Media 3, Appendix A lists the page properties one by one (margin-top to margin, padding-top to padding...) and 4.3 says "The @page rule can only contain page properties and margin at-rules."; the logical margin-inline and padding-block are not on the list, and Chromium 156 and Firefox 158 both keep them, as they keep a logical property wherever its physical one applies.
