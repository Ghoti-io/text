# The divergences of the style sheet and selector differential (css_sheet_diff.py) that are not this library's: a feature, its class, how many questions of the default
# population (seed 1, 200 documents) diverge, and the reason with the sentence of the served text that decides it. Tab separated. A divergence that is `ours` is never
# listed: the browsers agree and this library does not, and that is a defect.
#
# classes: browsers (the two browsers disagree and this library is with one of them)
# A count of 0 is a feature that only a hunt (another seed, or more documents) has met: the default population does not have it, so its count is not checked there.
z:lang-quoted-string	browsers	57	Selectors 4, 9.1 (the linguistic pseudo-class), the grammar ":lang( [ <ident> | <string> ]# )" takes a quoted language range ("*-CH" is the wildcard range of RFC 4647 extended filtering), and Firefox 158 accepts it; Chromium 156 throws a SyntaxError for the selector. The library follows the draft.
v:lang-quoted-string	browsers	9	The same selector in a style rule: Chromium 156 drops the whole rule (an invalid selector makes its rule invalid, Selectors 4 3.6), so the declarations of the rule do not apply there; Firefox 158 applies them, as does the library.
v:host-context	browsers	28	CSS Shadow 1 defines ":host-context()": it "matches the shadow tree's shadow host if the shadow host or one of its shadow-including ancestors matches the provided <compound-selector>". Chromium 156 implements it. Firefox 158 does not implement it (the selector is invalid there, so the rule is dropped and its declarations do not apply). The library follows the draft, with Chromium.
v:part-nested-under-a-selector-that-is-not-the-host	browsers	0	A `&::part()` nested in a rule of a shadow tree's own sheet whose selector is not `:host` (here `x-host`, and `div :host`, whose ancestor is not in the shadow tree): Firefox 158 applies it to the parts of the host, Chromium 156 does not. CSS Scoping 1: "When considered within its own shadow trees, the shadow host is featureless", matched by :host, :host() and :host-context() alone, so the parent selector represents nothing there and the nested rule has no subject. The library is with Chromium.
v:part-rule-with-a-nested-ampersand	browsers	0	A `&` nested in a `:host::part(a)` rule: CSS Nesting 1: "a parent selector containing a pseudo-element represents nothing", so the nested declarations apply to no element. Chromium 156 applies none; Firefox 158 applies them to the part. The library is with Chromium.
