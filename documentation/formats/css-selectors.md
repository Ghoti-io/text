# Selectors

Selectors Level 4 as a compiled form: a parser for every selector the specifications list, a serializer that is CSSOM's, the specificity, and what a selector asks of
the caller's tree. This page is the syntax and the compiled form; matching, the style sheet and the index come after it.
Back to \ref text_format_references "Formats".

Include `<ghoti.io/text/css.h>` (`css/css_selector.h`).

## Parsing

`gtext_css_selector_parse()` reads text, `gtext_css_selector_parse_values()` the component values of a style rule's prelude (the spans are then those of the style
sheet). Both return a `GTEXT_CSS_Selector_List`: immutable, reference counted with atomic counts, shareable between threads, with an `id` and a span in the bytes it was
read from on every node. **A selector that is not valid is an answer, not a failure**: the call returns `GTEXT_CSS_OK`, the list is `NULL`, and the result holds a
diagnostic (`kind`, span, and a reference to the sentence of the draft that decides it). A failure is an argument, memory or one of three limits, each its own status:
`GTEXT_CSS_E_LIMIT_SELECTOR_COMPONENTS`, `_LIST` and `_DEPTH` (the depth is capped at 256, and the parser recurses no further than that).

The mode says which list of the grammar is read:

| Mode | Where it is used | An entry that is not a selector |
|---|---|---|
| `GTEXT_CSS_SELECTOR_COMPLEX_LIST` | a style rule, `querySelector()` | the whole list is invalid |
| `GTEXT_CSS_SELECTOR_FORGIVING_LIST` | the argument of `:is()` and `:where()` | kept as written and never matched |
| `GTEXT_CSS_SELECTOR_RELATIVE_LIST` | `:has()`, nested rules | the whole list is invalid; each may begin with a combinator |
| `GTEXT_CSS_SELECTOR_COMPOUND` | `:host()`, `::slotted()`, `:host-context()` | one compound selector |
| `GTEXT_CSS_SELECTOR_REAL_LIST` | `:not()`, the `of S` of `:nth-child()` | invalid; no pseudo-element |

The Working Group resolved that a forgiving list **preserves** what it cannot read (csswg-drafts 8356): `:is(.a, ::bogus)` is written back as it was, the entry has
`raw` set and `never`, and it has no specificity. An empty argument is an empty list that matches nothing, with specificity zero.

## The selectors are data

Which pseudo-classes and pseudo-elements exist, what each takes as an argument, what may follow a pseudo-element, which state bits and callbacks a match asks the
caller for, the specificity rule and the status in this library are the rows of `tools/css/selectors.tsv`, generated by `tools/css/gen-selector-tables.py` from the
`selectors` data of the pinned webref (159 selectors) and `tools/css/selectors-supplement.tsv` (what webref omits, and the semantics of each row). `make
check-css-selectors` regenerates both generated files and fails on a difference, on a selector of the pin that has no row, on a stale row, and on an implemented row
that `tests/css_selector_rows.h` has no probe for; its `--controls` make each mistake in a copy and require the report. An unknown or vendor-prefixed name is not a
row, and its selector is invalid. A row is `implemented` (parsed, written and matched), `parse-only` (parsed and written; a match is `GTEXT_CSS_E_UNSUPPORTED` or never:
the column combinator `||` and `:nth-col()`, `:current()`, `:active-view-transition-type()`) or `unsupported` (the page selectors `:first`, `:left`, ... and
`:link-to()`: invalid in a style rule).

## Specificity

Exactly the draft's: a type selector or a pseudo-element counts in C, a class, an attribute selector or a pseudo-class in B, an id in A; `:is()`, `:not()`, `:has()` and
the `of S` of `:nth-child()` take the most specific complex selector of their argument; `:where()` is zero; `:host(S)` and `:host-context(S)` add S; `::slotted(S)` is a
pseudo-element plus S; a chain of pseudo-elements counts each. `#a .b:not(.c, #d) > p` is (2,1,1). The components saturate at `UINT32_MAX` and do not wrap. The nesting
selector `&` is the most specific selector of the list it stands for: a parse alone takes it as `:scope`, (0,1,0), and `gtext_css_complex_specificity()` recomputes with the
parent's.

## Serializing

`gtext_css_selector_serialize()` is CSSOM's "serialize a group of selectors" and writes `, ` between the selectors. A parse of its output is the same selector (the
fuzz harness checks the fixed point): `[att=val]` is `[att="val"]`, `:nth-child(odd)` is `:nth-child(2n+1)`, `a>b` is `a > b`, a universal selector that others follow is
not written, `:before` is `::before`, `:matches()` is `:is()`.

## What a selector asks of the caller

`gtext_css_selector_requires()` gives the element callbacks and the state bits that matching a list calls, so that a consumer checks its interface once, at compile time
(`gtext_css_selector_check_interface()` does it and names the first callback that is absent), and `gtext_css_selector_dependencies()` the summary that an invalidation pass
reads: the kinds of change that can affect the selector (name, id, class, attribute, state, ancestors, siblings, `:nth-*`, `:empty`, `:has()`, `:lang()`, `:dir()`, ...), the
state bits and the attribute names.

The element interface (`css_element.h`) grew for selectors, additively: `first_child`, `last_child`, `child_content`, `tree_scope`, `containing_host`, `shadow_scope`,
`assigned_slot`, `has_part`, `custom_state` and `column_cell`, and state bits 26 to 62 for the dynamic and input pseudo-classes the first 26 lack. A caller built before has a
smaller table and sees `GTEXT_CSS_E_UNSUPPORTED` naming the callback a selector needs.

## Tested scope

`make conformance-css-selectors` scores the 619 selector vectors of web-platform-tests (the `test_valid_selector`, `test_valid_forgiving_selector` and
`test_invalid_selector` calls, each selector read as `insertRule(selector + "{}")` reads it): 578 pass and 41 are exceptions, all of tentative pages that no served draft
specifies (the class-prefix selector `.foo-*` and the functional `:has-slotted()`); the 101 rule vectors are listed as not scored, with the page that scores each.
`make check-css-selector-plants` shows the unit tests fail on planted defects, and `tests/fuzz/fuzz_css_selector.cpp` is the libFuzzer harness (its seeds are replayed by
`make test`).
