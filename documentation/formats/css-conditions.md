# CSS conditions: media queries

`css_media.h` and `css_condition.h` implement Media Queries 4 and 5.

- `gtext_css_media_list_parse()` reads a `<media-query-list>` into an immutable, reference counted AST. An invalid query is replaced by `not all` (with a diagnostic); an unknown feature is `<general-enclosed>` and evaluates unknown; a known feature written wrongly (a value of the wrong kind, a prefix on a discrete feature, a mixed range) is one unknown leaf kept as written, so `(color: foo) or (color)` is true, as in browsers. A `<general-enclosed>` whose contents are not an `<any-value>` (an unmatched `}`, a bad string or url) makes the condition invalid.
- `gtext_css_media_list_serialize()` is CSSOM's serialization; parse, serialize, parse is a fixed point.
- `GTEXT_CSS_Media_Environment` is size-prefixed plain data. A feature is evaluated only if its bit in `supported` is set; any other feature is unknown, so false. `gtext_css_media_environment_default()` is a 1280 by 800 screen baseline.
- `GTEXT_CSS_Conditions` evaluates lists three-valued (Kleene; unknown at the top is false). It is immutable and shareable; a change of environment is a new object. `GTEXT_CSS_Condition_Call` carries the memo and counters.
- `@custom-media` definitions live in `GTEXT_CSS_Condition_Defs`; cycles are found when the conditions object is made and every name on one is undefined (unknown). The option `custom_media` off gives the browsers' behavior.
- Font-relative units in feature values use the environment's default font size (`font_metric` for `ex`, `ch`, `cap`, `ic`); without the callback they are `GTEXT_CSS_E_UNSUPPORTED`. `lh` and `rlh` need no callback: the initial `line-height` is `normal`, taken as 1.2 em. A keyword feature's `no-preference` (and `none`) is false in a boolean context, so `(prefers-reduced-motion)` is false at the defaults. Ratios are compared exactly.

The feature table is generated by `tools/css/gen-condition-tables.py` from the pinned webref data (`make check-css-conditions`).

## `@supports`

`gtext_css_supports_parse()` reads a `<supports-condition>` into the same AST as a media query list (`GTEXT_CSS_Supports_Condition`); the same evaluator answers it (`gtext_css_conditions_evaluate_supports()`), and `gtext_css_conditions_supports()` and `gtext_css_conditions_supports_text()` are `CSS.supports(prop, value)` and `CSS.supports(text)`.

- A declaration is supported when the registry knows the property and the value is valid for it by the cascade's own parser, with quirks off; `!important` is accepted and ignored; a custom property is supported with any `<declaration-value>` (the empty value too; not `--` alone). `selector()` is false for a forgiving list that skipped an empty entry (`:is(a,)`) or kept one it could not read, and for a selector this library only parses (`:nth-col()`); `at-rule(@charset)` is false. `GTEXT_CSS_Support_Policy::property_supported` narrows the set.
- `selector()` is supported when the text is one complex selector (a pseudo-element allowed, no relative selector), no forgiving list in it kept an entry it could not read or is empty, and, with an `element_interface` in the options, the interface has the callbacks the selector needs. An invalid selector is false.
- `font-tech()` and `font-format()` are answered from the policy's bit sets (a zeroed policy supports none). An identifier outside the grammar is `<general-enclosed>`. A string in `font-format()` names a MIME type, which is a valid feature that is false.
- `at-rule()` is true for the at-rules this library implements, narrowed by the policy. `named-feature()` and `env()` are answered by the policy's callbacks; without them they are false.
- **`<general-enclosed>` is false, not unknown** (Conditional 3: "Removed the 'unknown' value ... defining unrecognized syntaxes as 'false' instead"), so `not (foobar)` is true. Media queries keep the unknown value.
- A condition that does not parse (`@supports display: grid`, `and` mixed with `or`) is replaced and false; `CSS.supports(text)` accepts a bare declaration.

## `@when` and `@else`

`gtext_css_when_parse()` reads a `<boolean-condition>` of Conditional 5: `not`, `and`, `or` and parentheses over the leaves `media( <media-feature> )` and `supports( <declaration> | <supports-condition> )`, and, as the draft's own examples write them, the supports functions (`font-tech()`, `selector()` ...) directly. It is the same AST and evaluator (`gtext_css_conditions_evaluate_boolean()`). A `media()` whose feature is unknown is unknown; one that is known and written wrongly is false; `<general-enclosed>` is unknown (so `not` of it is unknown, and unknown at the top is false). A chain is evaluated by the sheet (\ref format_css_sheets "css-sheets.md"): "If one of them is true, the conditions of all following conditional group rules in the chain evaluate to false".

## Container queries

`css_container.h` implements `@container` (Conditional 5, 5 and 6). `gtext_css_container_parse()` reads `<container-condition>#` (`[ <container-name>? <container-query>? ]!` for each entry) into the same AST; **a condition that does not match the grammar makes the whole rule invalid** (a list that is `not all`), and an unknown feature (`(asdf)`, `(resolution > 100dpi)`, `foo(width)`, `(width == 1px)`) is `<general-enclosed>` that **selects no container**, so the condition is false.

- **The library lays nothing out.** The caller gives a `GTEXT_CSS_Container_Interface` in the options of the conditions object: `computed_style(element)` (the already computed style of an ancestor; ancestors are computed before their descendants, so it never forces a cycle), `content_box(container)`, `scroll_state(container)`, `anchored_fallback(container, value)` and `compute_context` (the context the styles were computed with, which a style query computes the queried value in). Each is optional; a query that needs one the caller did not give is `GTEXT_CSS_E_UNSUPPORTED` naming it (`container.size`), never a guess. A caller that supplies only `computed_style` (a document without layout) has no size container: a size query is false.
- **The query container** of an element is the nearest flat-tree ancestor (the element interface's `inheritance_parent`; for a pseudo-element other than `::slotted()` and `::part()`, the element itself first) that is a container for every kind of feature the condition asks (`size` or `inline-size` for size features, `scroll-state`, `anchored`, and any element for `style()`), and that has the name when one is given. **Container names are not tree-scoped** (Conditional 5, 5.2: "Container names are not tree-scoped names"). No container: unknown, so false. Each condition of a list selects its own container and the list is true if any is.
- **Size features** `width height inline-size block-size aspect-ratio orientation` (range, boolean and plain forms, `min-` and `max-` on the range ones) are evaluated by the same range evaluator as media features against the container's content box, `em` being the **container's** font size. The query container is chosen for the whole condition, among those that support every axis it asks about: an `inline-size` container is passed over by `(height > 1px)`, by `(aspect-ratio)` and by `(width < 1px) or (height > 1px)`, the search goes on to the ancestors, and a condition that finds none is unknown. The logical features follow the container's writing mode.
- **Style queries** compare computed values: `style(--theme: dark)`, `style(--theme)` (not the guaranteed-invalid value), `style(color: red)`, `style(color)` (differs from the initial value), `style(--n > 5)`. The queried value is computed as a declaration of the container, so `red` and `#f00` are equal for a color, `em` is the container's, and `var()` reads its custom properties; a CSS-wide keyword is computed on the container itself, and `revert` and `revert-layer` make the query false.
- **Scroll-state** `stuck snapped scrollable scrolled` map their logical keywords through the container's flow; a keyword matches only a container that is sticky (a scroll container, a snap target). `anchored(fallback: ...)` asks the caller.
- **Cost.** The container of an element for a request is its parent's answer when the parent is not one: the walk over a tree is O(elements x requests), asserted by the counters of `GTEXT_CSS_Condition_Call` (`container_steps`, `container_hits`, `container_requests`). **A call is the memo of one snapshot of the tree**; make a new one (or `gtext_css_condition_call_reset()`) when a style or a size changes. Distinct (name, kinds) requests are limited by `max_container_requests` (default 4,096, `GTEXT_CSS_E_LIMIT_CONTAINER`).
- `gtext_css_container_environment_size()` answers the `cq*` units from the same containers, so a `cqw` in a declaration and a `width` in a query are one fact.

An example: a media query list asked in a 600 px wide environment. An unknown feature value makes one leaf unknown, and the rest of the list still decides.

```c
#include <ghoti.io/text/css.h>
#include <stdio.h>
#include <string.h>

/* matchMedia(): a media query list is data, and the answer depends on the environment it is asked in. */
static void conditions_media(void) {
  GTEXT_CSS_Media_Environment env = gtext_css_media_environment_default(NULL);
  env.viewport.width = 600;
  GTEXT_CSS_Conditions_Options options = gtext_css_conditions_options_default();
  options.media = &env;
  GTEXT_CSS_Conditions * conditions = NULL;
  if (gtext_css_conditions_new(NULL, &options, &conditions) != GTEXT_CSS_OK) {
    return;
  }
  const char * queries[] = {"(min-width: 40em)", "(width > 700px)", "(color: foo) or (color)", "not all"};
  for (size_t i = 0; i < sizeof queries / sizeof *queries; i++) {
    bool matches = false;
    if (gtext_css_conditions_matches_media(conditions, queries[i], strlen(queries[i]), NULL, &matches) == GTEXT_CSS_OK) {
      printf("%s: %s\n", queries[i], matches ? "true" : "false");
    }
  }
  gtext_css_conditions_free(conditions);
}
```

prints

```
(min-width: 40em): false
(width > 700px): false
(color: foo) or (color): true
not all: false
```

And `@supports`, which asks the registry. A value the grammar refuses is not supported; an unmatched closer makes the whole condition invalid.

```c
#include <ghoti.io/text/css.h>
#include <stdio.h>
#include <string.h>

/* CSS.supports(): a declaration is supported when the registry's grammar accepts its value, and an unknown thing is false. */
static void conditions_supports(void) {
  GTEXT_CSS_Registry * registry = NULL;
  GTEXT_CSS_Conditions * conditions = NULL;
  GTEXT_CSS_Conditions_Options options = gtext_css_conditions_options_default();
  if (gtext_css_registry_new(NULL, &registry) != GTEXT_CSS_OK || gtext_css_conditions_new(registry, &options, &conditions) != GTEXT_CSS_OK) {
    return;
  }
  const char * conditions_text[] = {"(display: grid)", "(display: bogus)", "not (display: bogus)", "(--x: a;b)", "selector(:is(a, b))", "(foo: red})"};
  for (size_t i = 0; i < sizeof conditions_text / sizeof *conditions_text; i++) {
    bool supported = false;
    if (gtext_css_conditions_supports_text(conditions, conditions_text[i], strlen(conditions_text[i]), &supported) == GTEXT_CSS_OK) {
      printf("%s: %s\n", conditions_text[i], supported ? "supported" : "not supported");
    }
  }
  gtext_css_conditions_free(conditions);
  gtext_css_registry_free(registry);
}
```

prints

```
(display: grid): supported
(display: bogus): not supported
not (display: bogus): supported
(--x: a;b): not supported
selector(:is(a, b)): supported
(foo: red}): not supported
```
