# CSS conditions: media queries

`css_media.h` and `css_condition.h` implement Media Queries 4 and 5.

- `gtext_css_media_list_parse()` reads a `<media-query-list>` into an immutable, reference counted AST. An invalid query is replaced by `not all` (with a diagnostic); an unknown feature is `<general-enclosed>` and evaluates unknown.
- `gtext_css_media_list_serialize()` is CSSOM's serialization; parse, serialize, parse is a fixed point.
- `GTEXT_CSS_Media_Environment` is size-prefixed plain data. A feature is evaluated only if its bit in `supported` is set; any other feature is unknown, so false. `gtext_css_media_environment_default()` is a 1280 by 800 screen baseline.
- `GTEXT_CSS_Conditions` evaluates lists three-valued (Kleene; unknown at the top is false). It is immutable and shareable; a change of environment is a new object. `GTEXT_CSS_Condition_Call` carries the memo and counters.
- `@custom-media` definitions live in `GTEXT_CSS_Condition_Defs`; cycles are found when the conditions object is made and every name on one is undefined (unknown). The option `custom_media` off gives the browsers' behavior.
- Font-relative units in feature values use the environment's default font size (`font_metric` for `ex`, `ch`, `cap`, `ic`); without the callback they are `GTEXT_CSS_E_UNSUPPORTED`.

The feature table is generated by `tools/css/gen-condition-tables.py` from the pinned webref data (`make check-css-conditions`).

## `@supports`

`gtext_css_supports_parse()` reads a `<supports-condition>` into the same AST as a media query list (`GTEXT_CSS_Supports_Condition`); the same evaluator answers it (`gtext_css_conditions_evaluate_supports()`), and `gtext_css_conditions_supports()` and `gtext_css_conditions_supports_text()` are `CSS.supports(prop, value)` and `CSS.supports(text)`.

- A declaration is supported when the registry knows the property and the value is valid for it by the cascade's own parser, with quirks off; `!important` is accepted and ignored; a custom property is supported with any value. `GTEXT_CSS_Support_Policy::property_supported` narrows the set.
- `selector()` is supported when the text is one complex selector (a pseudo-element allowed, no relative selector), no forgiving list in it kept an entry it could not read or is empty, and, with an `element_interface` in the options, the interface has the callbacks the selector needs. An invalid selector is false.
- `font-tech()` and `font-format()` are answered from the policy's bit sets (a zeroed policy supports none). An identifier outside the grammar is `<general-enclosed>`. A string in `font-format()` names a MIME type, which is a valid feature that is false.
- `at-rule()` is true for the at-rules this library implements, narrowed by the policy. `named-feature()` and `env()` are answered by the policy's callbacks; without them they are false.
- **`<general-enclosed>` is false, not unknown** (Conditional 3: "Removed the 'unknown' value ... defining unrecognized syntaxes as 'false' instead"), so `not (foobar)` is true. Media queries keep the unknown value.
- A condition that does not parse (`@supports display: grid`, `and` mixed with `or`) is replaced and false; `CSS.supports(text)` accepts a bare declaration.
